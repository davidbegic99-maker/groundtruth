STEP 1 — Foundation & app shell
  - Server starts cleanly on Node 24 using Node's built-in database engine
    (no fragile native install). Health, stats and settings endpoints all
    answered correctly when tested live.
  - The "5 reports within 200 metres" PDF rule is an EDITABLE SETTING, not
    hard-coded. There are 11 such tunable settings stored in the database.
  - All 6 UN languages are present and EXACTLY in step with each other
    (188 text entries each, no gaps) for the whole Reporter flow. Arabic is
    set up to mirror right-to-left.
  - Offline-first app shell (service worker) and an installable app manifest.
  - Two clearly labelled views: "Reporter View" and "Analyst View".

STEP 2 — Reporter flow, part 1: photos & location
  - Up to 3 photos; privacy guidance overlay before the first photo.
  - Reads GPS + time from a photo's hidden data; full location fallback chain
    (photo GPS -> live device GPS -> tap the map -> describe a landmark ->
    accept with no location). A report is never blocked by missing location.
  - Photos are shrunk in the browser and ALL hidden metadata is removed for
    privacy; each photo gets a fingerprint (hash).
  - Interactive map with real OpenStreetMap tiles and a draggable pin.

STEP 3 — Reporter flow, part 2: hazard, AI, confirmation
  - Two-step emergency picker covering all 9 hazard types.
  - AI suggests a damage level + building type + a confidence score. It works
    even with NO AI key (a built-in sample mode), so evaluators need nothing.
    Tested live: returned a clean Minimal/Partial/Complete result.
  - The AI's internal "damage percentage" is analyst-only and never shown to
    the public.
  - Confirm/correct screen; the mandatory "are people in danger?" question
    sets the priority flag; two optional hazard-specific questions; safety
    warnings for Conflict and Chemical incidents; a final review screen.

STEP 4 — Submit & offline queue
  - Submitting really saves. Online -> green "submitted" with a mini-map.
    Offline -> orange "saved, will upload later" with a waiting count, then it
    uploads automatically when the connection returns (plus a manual "Sync now"
    button and best-effort background sync).
  - Photos are stored AES-256 encrypted; device IDs are stored only as one-way
    hashes; the photo's capture time is preserved (not the upload time); the
    AI-vs-user conflict flag is computed; repeat buildings are versioned; and a
    re-sent report is ignored so nothing duplicates.
  - Verified live: a stored photo could be DECRYPTED back into a real image
    (only with the analyst key; blocked without it).

STEP 6 — Exports & data sharing: FULLY DONE AND VERIFIED  (closes the GIS must-pass)
  - CSV download: flat table with the mandatory fields plus submission_id, hazard,
    channel, location method, priority flag, building id/version. Verified.
  - GeoJSON download + REST API: proper point FeatureCollection (WGS84/CRS84) with
    all mandatory fields as properties. Verified it parses; null-coordinate reports
    kept with null geometry so nothing is dropped.
  - GeoPackage (.gpkg) download: a genuine, spec-valid OGC GeoPackage built with no
    third-party GIS library. Verified: correct SQLite + GPKG signature, all required
    metadata tables, 4326/WGS84 CRS, decodable point geometry, correct bounding box.
    It opens directly in GIS tools such as QGIS.
  - REST API (/api/v1/reports): authenticated GET returning filtered GeoJSON. Honours
    bbox, time range, damage tier, hazard, infrastructure, priority. Filters verified
    (priority -> 5, Complete -> 5). The dashboard shows the live endpoint URL + a copy
    button; the URL updates as filters change.
  - PDF area summary (§13.3): on-demand "PDF summary" button generates a real, valid
    one-page PDF (verified structurally: header, xref, fonts, embedded photo, EOF) with
    tier breakdown chart, schematic cluster map, infrastructure list, dominant hazard,
    time range, and the highest-confidence report's photo. Auto-trigger detection also
    works: the dashboard flags areas that reached the configurable threshold (default
    5 within 200 m) — it correctly found the 7-report Sultanahmet cluster.
  - Post-sync AI de-duplication (§4.3): runs after each sync (never blocks submission),
    computes a perceptual photo hash, and writes the analyst annotation. Verified it
    produced the briefing's example phrasing for the 3-version building, incl. a
    near-identical-photo note. Shows in the detail panel.
  - Server-side translation (§10.4): LibreTranslate integration that stores the English
    translation + detected language alongside the original. Optional and fails safe —
    if no LibreTranslate endpoint is configured (the default offline demo) it is simply
    skipped and the original text is kept. Enable via the LIBRETRANSLATE_URL env var.
  - All new dashboard text added to all 6 languages (248 entries each, in step);
    Arabic export UI confirmed translated and right-to-left; no console errors.
